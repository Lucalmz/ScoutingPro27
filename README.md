# ScoutingPro27 🚀

ScoutingPro27 是一款专为 FIRST Tech Challenge (FTC) 打造的现代化、高可用、离线优先的赛事侦察与数据分析桌面应用。本项目致力于在赛场缺乏稳定网络连接的极限恶劣环境下，为车队提供极速、安全、可靠的数据同步与队伍战力深度剖析服务。

**得益于纯去中心化的底层架构，本项目彻底抛弃了中心化云数据库与繁琐的服务器部署。在技术实现上，我们将极轻量级的 H2 数据库引擎（携带自动 `AUTO_SERVER` 混合模式）直接内嵌于本地 Java 进程中，所有侦察数据落地于物理机本地；同时通过 WebRTC DataChannel 建立局域网/公网的设备直连，实现内存级别的数据对撞同步。这意味着：对于任何想要使用的高校或车队，ScoutingPro27 真正做到了“零依赖、开箱即用”——无需购买云服务，无需配置 Docker 容器，无需架设复杂的网络路由硬件，只需双击打开，战力即生。**

## 🌟 主要功能 (Features)
- **多端离线协作**：支持赛事现场的无网/弱网环境，本地缓存侦察数据，待局域网或公网连接建立后自动双向同步。
- **智能化表单录入**：支持单机或双机侦察模式，提供防重录入、自增运算等全自动错误拦截。
- **动态能力排行榜**：基于历史数据计算出精准的队伍得分能力，并附带直观的战力走势分析（`↗` / `➡` / `↘`）。
- **赛事内网即时通讯**：Host 与 Scout 可直接通过点对点直连进行加密的文字通讯与任务分发。
- **官方数据一键比对**：可随时接入 FTC 官方数据源核对成绩，自动剔除赛场违规得分中的水分。

## 💀 核心底层架构与技术“深水区” (Hardcore Tech Deep Dive)

相较于社区内千篇一律的常规 Web 填表或移动端 App 开发模式，ScoutingPro27 在底层架构选型与网络通信机制上做出了**极具突破性的创新**。

### 1. 颠覆性的公网 STUN 穿透与零成本 P2P (WebRTC + MQTT)
在 FTC 社区中，绝大多数团队的数据同步高度依赖租用昂贵的云服务器进行中心化转发，一旦现场断网或服务器崩溃，系统直接瘫痪。
- **极其创新的社区玩法**：本项目创造性地引入了 **WebRTC 配合公网 STUN 服务**，将原本用于音视频会议的底层协议“降维”应用在纯数据同步上，利用公网穿透在端与端之间建立纯净的 DataChannel，这在 FTC 技术圈内是一次极其创新的尝试。
- **免费公共信令桥梁**：基于免费的 `broker.emqx.io:8084` (MQTT WebSocket) 交换 SDP 和 ICE 候选者，彻底免除了搭建专属信令服务器的高昂开销。
- **哈希隐匿与星状拓扑**：采用 Web Crypto API 对邀请码进行不可逆散列，生成唯一的信令 Topic 避免撞车，并在此之上自行搭建了一套以 Host 为中心的**星状网自愈拓扑**——任何节点数据的改变都会被自动广播分发，实现去中心化后的全网绝对一致。

### 2. 远超同类的桌面端解法：JCEF 深度定制隔离
在桌面端打包方案上，大部分团队会选择极其臃肿的 Electron（自带 Node.js 庞大环境，严重消耗内存）或老掉牙的 Java Swing 控件。
- **更高级的底层掌控 (JCEF)**：ScoutingPro27 选用了极为硬核的 **JCEF (Java Chromium Embedded Framework)**，直接在纯血 Java 进程中拉起由 C/C++ 编写的 Chromium 核心。该方案避开了 Node.js 的性能损耗，在保证现代化 Web 渲染极速响应的同时，榨干了本地机器的每一滴算力。
- **暴力破解“多开死锁”**：Chromium 内核底层有极严厉的保护机制，禁止多个进程共享同一个 `user_data_path` 缓存，否则会引发严重的文件锁死崩溃。为此，我们在 Java 启动层强行劫持了内核初始化参数，利用 `java.io.tmpdir` 配合动态 `UUID` 为每次启动的沙盒暴力分配独立缓存，并在退出 Hook 中注入了递归销毁指令，完美实现了**突破内核封锁的“无限高并发多开”测试能力**。

### 3. 应对赛场恶劣环境的离线补偿队列 (Offline Auto-Flush Queue)
- **命令级断线补偿**：为了应对赛场设备随时断网、休眠的梦魇环境，Host 发送给断线侦察员的底层通讯指令会被自动截获，并封存在后端的 `offlineMessages` 暂存队列中。
- **恢复即冲刷**：一旦节点恢复网络并发出底层的 `REQUEST_SYNC` 握手探针，Host 监听到上线信号后，会瞬间将挂起的所有指令全量**冲刷 (Flush)** 给该客户端，确保数据与指令“绝对到达”。

### 4. 接入官方 GraphQL 的信誉度降维打击算法
- 系统不仅接入 `api.ftcscout.org/graphql` 获取真实赛事的官方得分（精确剥离违规罚分），更开发了一套独创的**侦察员信誉降维算法**。
- 底层会将每位 Scout 提交的成绩单与官方总分进行“机器阅卷”式的比对。一旦该侦察员的平均误差率越过 `20%` 的红线，其数据信任级别会瞬间跌落至 `'low'`。在最终计算战队大榜时，其数据的计算权重会被系统强行砍半（`0.5`）。从算法引擎的维度直接粉碎了赛场“乱打分”对整体数据池的污染。

### 5. 应对海量并发覆盖的优雅幂等 SQL
- 为了防御在网络极其恶劣时发生的数据频繁冲突与无脑冲刷，后端的 H2 数据库利用了底层方言 `MERGE INTO`，并嵌套了时间戳劫持子查询：
  ```sql
  COALESCE((SELECT created_at FROM scouting_records WHERE id = :id), COALESCE(:createdAt, CURRENT_TIMESTAMP))
  ```
  该语句从数据库引擎的最底端保证了：无论一条数据经历了多少次断线重传和互相覆盖，其诞生的最初时间戳 `created_at` 都固若金汤，绝不丢失。
